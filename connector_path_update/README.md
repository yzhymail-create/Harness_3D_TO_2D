# 连接器到连接器全局最长路径分析

本目录是独立算法模块，按 segment 级拓扑计算任意两个不同末端连接器之间的最长简单路径。一个 branch 可以由多条 segment 组成，搜索时逐段保留；不会把一个 branch 错误简化为单根管段。

## 算法规则
- 节点：topology.json 的 nodes。
- 边：segments 中的每条管段；一个 branch 可以包含多条 segment。
- 权重：segments[].length 的 3D 真实长度，不是 XY 投影长度。
- 目标：两个不同连接器之间的最长简单路径；路径中的节点不能重复。
- 路径允许经过中间连接器后继续到另一个连接器。
- 自环（na == nb）不能构成简单节点路径，单独列入 ignored_self_loops。
- 输出连接器端点、总长、节点序列、segment/branch 序列、逐段明细和搜索状态数。

## 优化后的搜索策略
1. 先按拓扑连通分量拆分，绝不跨不连通分量拼接路径。
2. 无环分量是树：用两次加权树遍历求连接器终端集合的直径，复杂度 O(V+E)，不枚举所有路径。
3. 含环或平行边的分量：使用精确 DFS，每个起点只遍历一次，同时评估所有后续连接器；节点访问集合保证路径简单，并用“当前长度 + 所有未使用边权重”作为安全上界剪枝。
4. 所有邻接边按节点名、segment 名和内部序号排序；等长路径按连接器名及 segment 序列确定性择优。
5. 缺失节点引用、重复节点编号、缺失/非法长度、负数或非有限长度直接报错，不静默跳过。

注意：含环一般图的最长简单路径在理论上可能是指数复杂度；程序对树形线束做线性优化，对含环分量仍保持精确求解，不用近似值冒充精确结果。

## 运行
```bash
python connector_path.py topology.json -o connector_longest_path.json
python -m unittest discover -s tests -v
```

## 样例实测记录
原始实现曾在 110 节点、116 segment 样例上得到 CON01 → CON08、约 2341.4 mm，29 条 segment。优化版需在同一份输入上重新运行确认；不要把旧版搜索状态数当作优化版性能数据。

## 当前边界
本模块完成的是最长路径识别与审计。它尚未自动接管 v4 二维布局器的主干摆放；下一阶段必须同时处理主路径长度守恒、连接器端点定位、分支挂接与环约束，不能简单把整条路径强制拉成水平线。
